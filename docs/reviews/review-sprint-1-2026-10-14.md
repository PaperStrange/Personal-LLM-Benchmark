## Findings applied

**[BLOCKER] B1 (adversarial) — cap-abort `fail` lines fed the >10% rule.**
The runbook told operators to log cap aborts as `status: fail` while also
stating a cap abort is [INFRA] "never counted against a candidate's score" —
so an early cap abort could push a candidate over the 10% "not recommended"
bar through no fault of its own. Fixed: `cap_abort` lines are logged but
**excluded from the failure-rate computation** (runbook, "Reliability log").

**[MAJOR] M1 (adversarial) — `cost_usd` "never estimated" vs price-table
rationale.** The `--model` flag's documented purpose is pricing via a
per-model price table, which contradicted methodology.md's "never estimated".
Fixed: `cost_usd` is priced from *measured* usage — provider dashboards, or
measured tokens × published per-model prices. What it must never be is a
heuristic estimate (and never the judge-side chars/4 `est_cost_usd`).

**[MAJOR] M2 (adversarial) — S1.5 case 2 contradicted its premise.** The
example claimed the quality-per-dollar ratio "governs" when the winner is
unaffordable — but an unmeasured score (90, never graded at this budget) is
[OPEN], not an input to a ratio. Fixed: rule (a) restated as an affordability
gate — the raw winner drops out of the affordable set; among affordable
candidates, quality-per-dollar governs. Worked example rewritten accordingly
(also fixed the "ungradeable" typo, flagged by mistake-hunt).

**[MAJOR] M3 (both) — S1.2 AC asserted code that doesn't exist.**
"aggregate/scorecard code accepts and preserves it" was written against a
false premise: no code reads or writes `results/scorecard.csv` (rows are
hand-written by design; verified by grep across src/ and tests/). Fixed: the
AC in `docs/sprints/sprint-1-plan.md` now states the reality — header plus
documented semantics, no code path can read or drop the column.
